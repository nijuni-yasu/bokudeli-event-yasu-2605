# ユーザー決済手数料機能

## 1. 概要
### 1.1 機能の目的
決済処理のコストをカバーするため、ユーザー決済手数料を動的に計算してクレジットカード決済に上乗せする機能を提供する。

### 1.2 主要な機能
- 注文金額に応じた動的手数料計算
- 手数料を含む決済金額の表示
- 返金時の手数料除外処理
- 店舗向け表示での手数料除外
- 出前館型の **1 PDF・2 発行者ブロック** 領収書（店舗＝食事 / ニジュウニ株式会社＝決済手数料）

### 1.3 対象ユーザー
- イベント参加者（決済手数料を支払う側）
- イベント主催者・店舗（手数料を受け取らない側）

## 1.4 手数料
### 1.4.1 手数料計算式
- **計算ベース**: Stripe に実課金する **自己負担額**（メニュー合計 − 主催者負担 − 企業補助）。メニュー総額にはかけない。
- **計算式**: `ユーザー手数料 = MIN(220, MAX(110, FLOOR(自己負担額 × 0.1, 100) × 1.1))`
  - 実装同等: `selfPay <= 0 ? 0 : Math.min(220, Math.max(110, Math.floor(selfPay / 1000) * 110))`
  - 定数: `USER_PAYMENT_FEE_UNIT = 110`、`USER_PAYMENT_FEE_MAX = 220`（`common/src/utils/paymentUserFee.ts`）
- **計算手順**:
  1. 自己負担額に10%をかける
  2. 100の位で切り捨てる
  3. 1.1（消費税）をかける
  4. 最低 110 円、最大 220 円とする。ただし自己負担が 0 円なら手数料も **0 円**（最低110円は適用しない）
- **適用条件**: Stripe で実課金する決済のみ（§1.4.2）
- **Stripe 実費との関係**: 上限 220 円は高額注文でカード決済実費（約 3.6%）を下回ることがある。飲食店への支払いは決済実費を差し引いて行うため、ユーザー手数料の上限は問題にしない。

### 1.4.2 適用対象

| 支払い方式 | 手数料 |
|---|---|
| `user_advance`（参加者事前クレカ） | あり（メニュー額＝自己負担） |
| `community_bill` ＋ 割引で **差額あり** | あり（差額＝自己負担に対して） |
| `enterprise_subsidy` で **自己負担あり** | あり（自己負担に対して） |
| 当日払い（`user_on_day`） | なし |
| 請求書のみ / 自己負担 **0 円**（無料参加・全額補助など） | なし（Checkout しない） |

PayPay 等も Stripe Checkout 経由なら同じ式。請求書払い手数料（主催者向け 10%）とは別。

### 1.4.3 手数料計算例

| 自己負担額 | 計算過程 | 手数料 |
|---------|---------|--------|
| 0円 | Checkout しない | 0円 |
| 1,000円 | MIN(220, MAX(110, …)) = 110円 | 110円 |
| 2,000円 | 220円 | 220円 |
| 3,000円 | 330円 → 上限 220円 | 220円 |
| 3,500円 | 330円 → 上限 220円 | 220円 |
| 4,000円 | 440円 → 上限 220円 | 220円 |
| 10,000円 | 1,100円 → 上限 220円 | 220円 |

### 1.4.4 手数料の変動要因
- 自己負担額に応じて手数料が変動
- 将来的な手数料変更に対応するため、設定可能な仕組みを構築
- イベント単位での手数料設定は現時点では対応しない

## 4. 画面仕様
### 4.1 画面遷移
```
カート画面 → 決済確認画面 → Stripe決済画面 → 完了画面
     ↓
マイページ（注文履歴）
```

### 4.2 UI要素
#### 4.2.1 カート画面
- **表示内容**:
  - 商品小計: 1,000円
  - 決済手数料: 110円
  - 合計金額: 1,110円
- **表示位置**: 小計の下、合計金額の上
- **デザイン**: 手数料項目は明確に区別して表示
- **説明文**: 「決済手数料」の横の「？」を押すと表示する。文言は「参加者 事前決済」の手数料です。最低110円・最大220円。キャンセルしても返金されません。（金額の正は画面表示。式は規約に固定しない）

#### 4.2.2 Stripe決済画面
- **表示内容**: カート画面と同様の内訳表示
- **決済金額**: 合計金額（商品小計 + 手数料）で決済
- **手数料の明示**: 決済前に手数料を含むことを明確に表示

#### 4.2.3 マイページ（注文履歴）
- **表示内容**:
  - 商品金額: 1,000円
  - 決済手数料: 110円
  - 合計金額: 1,110円
- **表示形式**: 内訳を明確に分けて表示
- **金額の正本**: 残っている注文（`canceled` 以外）が属する `EventStripe.pay_user_fee_amount` の合計。同じ `stripe_id` は 1 回。未設定または 0（リリース前の決済を含む）のときは【決済手数料】と【合計金額】を出さず、自己負担額だけを出す。部分キャンセル後も自己負担から計算し直さない
- **説明文**: 「決済手数料」の横の「？」を押すと「最低110円・最大220円。キャンセルしても返金されません。」を表示する
- **注文詳細**: 各注文の詳細画面でも同様の表示

#### 4.2.4 店舗管理画面
- **表示制限**: 手数料を含まない商品金額のみ表示
- **店舗メール**: 手数料を含まない商品金額で通知
- **店舗支払い金額**: 手数料を除いた商品金額のみ

#### 4.2.5 イベントページ
- **キャンセルポリシー**: 手数料の返金不可を明記
- **表示例**: 「決済手数料は返金されません。金額はカートと注文履歴に表示します。」

#### 4.2.8 利用者・法務への明記

式の詳細は内部正本（本節）と `paymentUserFee.ts`。利用者向けは金額とルールだけを書く。

| 場所 | 書くこと |
|---|---|
| カート・注文履歴 | 手数料の円。「？」で最低110円・最大220円と非返金を表示 |
| キャンセルポリシー / キャンセル確認 | 決済手数料は返金されない |
| 利用規約 | 決済手数料があり得ること。金額は購入画面が正。料率は変更しうる。ユーザー都合キャンセルでも非返金 |
| 特定商取引法に基づく表記 | 追加料金として決済手数料。金額は購入画面。非返金。主催者請求書払い手数料は別 |
| 主催者向け「請求書払い」説明 | 「オンライン決済なら手数料なし」とは書かない。請求書払い手数料は主催者向け。参加者クレカには決済手数料がかかる |

#### 4.2.6 返金・キャンセル仕様

##### 4.2.6.1 返金ルール
- **返金対象**: 自己負担（食事代）のみ
- **返金対象外**: 決済手数料。キャンセルしても手数料分は返金しない
- **返金計算**: キャンセルした注文の自己負担合計。セッション手数料は残す
- Stripe 返金は現行どおり `Σ(menu_price − 割引)`。`pay_amount` が手数料込みでも、返金額に手数料を足さない

##### 4.2.6.2 キャンセル時の表示
- **マイページ**: キャンセル実行時に手数料返金不可を明記
- **確認ダイアログ**: 「決済手数料は返金されません」を表示
- **キャンセルポリシー**: イベントページに事前に明記

##### 4.2.6.3 部分キャンセル
- マイページは **メニュー単位キャンセル** が既にある。手数料はセッション（`EventStripe`）に 1 回だけ載せ、どのキャンセルでも返さない。
- 領収書の食事ブロックは返金後の残額、手数料ブロックは満額のまま（§4.2.7）。

### 4.2.7 領収書（出前館型・1 PDF / 2 発行者）

参考: 出前館「領収書（再発行）」PDF（店舗ブロック ＋ 株式会社出前館ブロックを 1 枚に載せる形式）。

発行単位は現行どおり **`stripe_id`（`EventStripe`）1 枚**。`eventReceipt` Callable が PDF を返す。

#### 4.2.7.1 方針

- **1 ファイル**に、発行者の異なる 2 ブロックを縦に並べる（書類を 2 通に分けない）。
- **店舗ブロック**: お食事代。軽減税率 **8%**（現行領収書と同じ）。発行者は開催店舗。
- **ニジュウニブロック**: ユーザー決済手数料。標準税率 **10%**。発行者はニジュウニ株式会社。
- 店の登録番号で手数料を発行しない。手数料の登録番号はニジュウニ株式会社固定。
- 手数料が無いレガシー決済（`pay_user_fee_amount` 未設定または 0）は、ニジュウニブロックを出さず、現行どおり店舗ブロックのみ。

#### 4.2.7.2 発行者（代理交付。媒介者交付特例ではない）

食事ブロックは店名義・店の登録番号を載せる **代理交付**（プラットフォームが店の領収書を代行して出す）。国税庁の **媒介者交付特例**（食事代をニジュウニ名義・ニジュウニの番号で出す）は使わない。特例専用の税務署申請・登録は不要。

店の登録番号が未設定のときは、その行を出さない（「なし」とは書かない）。コード・文言に「媒介者交付特例」は出さない。

| ブロック | 発行者名 | 適格請求書発行事業者登録番号 |
|---|---|---|
| 店舗（お食事代） | `shop.shop_name` | `shop.shop_invoice_number`。未設定は行を出さない |
| 決済手数料 | **ニジュウニ株式会社** | **`T8010001198825`**（固定。店舗マスタに持たない。ニジュウニ自身の売上） |

フッター（出前館の「この商品代金の領収書は出前館加盟店舗により発行するものです。」に相当）:

> このお食事代の領収書はイベント開催店舗により発行するものです。

ヘッダー項目の出前館対応:

| 出前館 | Shokujii |
|---|---|
| 発行日時 | PDF 生成時刻（再発行でも「再発行」表記。番号は初回採番のまま） |
| 店舗名 | `shop.shop_name` |
| 注文日時 | `EventStripe.created_at` |
| 配達日 | **イベント開催日**（`event.event_start_datetime` の日付） |
| 決済方法 | Stripe の支払手段が取れる場合はそれを出す。取れなければ「オンライン決済」 |
| 合計 | 金額の帯。お食事代と決済手数料を出したあと、`grand_total`（税込） |

#### 4.2.7.4 金額

税込円。内税の分解は既存ユーティリティに合わせる。

- 8%（食事）: `computeInclusive8ExTaxAndTax`（税抜 = `Math.floor(税込 / 1.08)`）
- 10%（手数料）: `computeInclusive10ExTaxAndTax`（税抜 = `Math.floor((税込 * 10) / 11)`。`110 / 1.1` の浮動小数誤差を避ける整数演算。税額 = 税込 − 税抜）

| 記号 | 定義 |
|---|---|
| `fee` | `EventStripe.pay_user_fee_amount ?? 0` |
| `food_charged` | `pay_amount - fee`（決済時の食事＝自己負担） |
| `refunded` | `refunds` の `amount` 合計（食事の返金のみ。手数料は返さない） |
| `shop_subtotal` | `max(0, food_charged - refunded)` |
| `grand_total` | `shop_subtotal + fee` |

全注文キャンセル後は領収書ボタンを出さない（現行どおり `ordered` が残っているときだけ）。

表示例（食事 1,000 円 ＋ 手数料 110 円、返金なし）:

| ブロック | 小計 | 表示する税率 | 税抜 | 消費税等 |
|---|---|---|---|---|
| 店舗 | 1,000 | 8% のみ | 925 | 75 |
| ニジュウニ株式会社 | 110 | 10% のみ | 100 | 10 |
| 金額（税込） | 1,110 | — | — | — |

食事 1,680 円 ＋ 手数料 240 円なら、出前館サンプル（1,680 / 内税 125、240 / 内税 22、合計 1,920）と同じ構造になる。

#### 4.2.7.5 メニュー行

- データは当該 `stripe_id` の **残 `ordered` の `member_orders`**。`EventStripe.menus` の割引前 `menu_price` は使わない（補助・主催者負担・部分キャンセルで小計とずれるため）。
- 表示単価は **食事の自己負担（税込）** = `menu_price − (pay_enterprise_subsidy_amount ?? pay_community_bill_off_amount ?? 0)`。手数料はメニューに按分しない。
- `menu_name` + 自己負担単価が同じ行は `count` で集約する。自己負担 0 円と `canceled` は出さない。
- 内訳の自己負担合計は `shop_subtotal`（`food_charged − refunded`）と一致する。
- 軽減税率対象には **※** を付ける（出前館と同じ）。食事行は現行どおり 8% のため全行 ※。
- 手数料はニジュウニブロックの「決済手数料」1 行だけ。※ は付けない。

#### 4.2.7.6 発行条件

- Stripe 実課金があり `pay_amount > 0` のときだけ発行する（現行の ¥0 拒否を維持）。
- `community_bill` の差額決済・`enterprise_subsidy` の自己負担決済も、`stripe_id` があれば同じレイアウト。
- 手数料 0 のレガシーは店舗ブロックのみ（8% 一式）。ニジュウニブロック・10% 行は出さない。

#### 4.2.7.7 実装メモ

- 正本は `EventStripe.pay_amount` と `pay_user_fee_amount`。Webhook 確定時に手数料を保存する（§5.1）。
- クライアントが手数料額を改ざんできないこと。
- ニジュウニ株式会社の登録番号 `T8010001198825` はコード定数（店舗・イベントのフィールドにしない）。
- 現行 `receipt.docx` は店 1 発行者・8% 一式なので、2 ブロック用にテンプレートを更新する。

## 5. 技術仕様・データ構造設計
### 5.1 Firestoreスキーマ

```typescript
// common/src/schemas/order.ts
import { z } from 'zod';

export const OrderMenuSchema = z.object({
  menu_id: z.string(),
  name: z.string(),
  price: z.number().positive(),
  count: z.number().int().positive(),
});

export const OrderSchema = z.object({
  orderId: z.string(),
  eventId: z.string(),
  userId: z.string(),
  
  // 注文されたメニュー（複数対応）
  menus: z.array(OrderMenuSchema),
  
  // 金額関連フィールド（実装正本は EventStripe。下記は草案当時の案）
  // EventStripe.pay_user_fee_amount?: number  // セッション手数料。未設定は 0（レガシー）
  // EventStripe.pay_amount は 自己負担 + 手数料（Stripe 実課金額）
  payment_user_fee_amount: z.number().min(110), // ユーザー決済手数料（動的計算）
  payment_user_total_amount: z.number().positive(), // 小計 + 手数料 = 合計金額
  payment_user_refund_amount: z.number().optional(), // 返金金額（合計金額 - 手数料）
  
  // 注文ステータス
  status: z.enum(['ordered', 'in_cart', 'canceled']),
  
  // タイムスタンプ
  canceled_at: z.date().optional(), // キャンセル日時
  ordered_at: z.date(),
  created_at: z.date(),
  updated_at: z.date(),
});

export type Order = z.infer<typeof OrderSchema>;
```

### 5.2 Functions設計
#### 5.2.1 Callable Functions（フロントエンドから呼び出し）
- `createOrderWithFee`: 手数料を含む注文作成
  - **引数**: `orderData: Partial<Order>`（注文データ）
  - **戻り値**: `{ orderId: string, paymentIntent: any }`（注文IDとStripe決済意図）
  - **認証**: 認証済みユーザーのみ
  - **処理内容**: 
    1. 商品小計から手数料を計算
    2. 手数料を含む注文データをFirestoreに保存
    3. Stripe決済意図を作成
    4. 決済情報をフロントエンドに返却

#### 5.2.2 Trigger Functions（自動実行）
- `onOrderCanceled`: 注文キャンセル時の返金処理
  - **トリガー**: Firestore `orders` ドキュメント更新時（status: 'canceled'）
  - **処理内容**: 
    1. 注文データから手数料を除外した返金金額を計算
    2. Stripe返金処理を実行
    3. 返金金額を注文データに記録
  - **権限**: システム権限

### 5.3 処理フロー

#### 5.3.1 手数料計算フロー
1. 自己負担額を算出（メニュー合計 − 主催者負担 − 企業補助）。サーバーが正本、カート表示は同じ関数でプレビュー
2. 自己負担が 0 なら手数料 0、Checkout しない
3. それ以外は `MIN(220, MAX(110, FLOOR(自己負担額 × 0.1, 100) × 1.1))`
4. 合計 = 自己負担 + 手数料。Checkout / Webhook はサーバー再計算

#### 5.3.2 注文作成フロー
1. フロントエンドでカート情報から商品小計を計算
2. 手数料計算ロジックで手数料と合計金額を算出
3. `createOrderWithFee` Functionを呼び出し
4. Function内で手数料を含む注文データをFirestoreに保存
5. Stripe決済意図を作成
6. フロントエンドに決済情報を返却

#### 5.3.3 返金処理フロー
1. ユーザーがキャンセルを実行
2. 注文ステータスを'canceled'に更新
3. `onOrderCanceled` Trigger Functionが自動実行
4. Function内で手数料を除外した返金金額を計算
5. Stripe返金処理を実行
6. 返金金額を注文データに記録

### 5.4 計算ロジック実装

```typescript
// フロントエンド用の手数料計算ロジック
// utils/calculateUserFee.ts
export const calculateUserFee = (selfPay: number): { fee: number, total: number } => {
  if (selfPay <= 0) return { fee: 0, total: 0 }
  // MIN(220, MAX(110, FLOOR(自己負担 × 0.1, 100) × 1.1)) と同等
  const fee = Math.min(220, Math.max(110, Math.floor(selfPay / 1000) * 110))
  return { fee, total: selfPay + fee }
}

// Functions用の返金金額計算
// functions/default/src/orders/refund.ts
export const calculateRefundAmount = (total: number, fee: number): number => {
  return total - fee; // 手数料を除いた金額
};
```
