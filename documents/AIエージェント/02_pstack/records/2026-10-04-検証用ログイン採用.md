# 1-6-6 初期採用方式（2026-10-04）

## 採用

| 環境 | 方式 | 証明範囲 |
| --- | --- | --- |
| ローカル / sandbox（`VERIFICATION_TEST_OUTBOX_MODE=record_skip_send`） | 既存メールログイン + テスト受け口 + ADC 認証済み CLI | ログイン後の画面・カート操作（Google OAuth 自体は証明しない） |
| 本番 | 受け口 **off**（既定）。実 SendGrid 配送のまま | pstack 検証対象外 |

## 根拠

- Shokujii のユーザーログインは SendGrid 経由の独自 OTP（`requestEmailLogin` / `confirmEmailLogin`）であり、Auth Emulator の標準コード取得だけでは代替できない（[03_検証用ログインの検討.md](../03_検証用ログインの検討.md)）。
- D-07 に従い、通常検証では `@verify.shokujii.test` 宛の OTP を Firestore `verification_test_outbox` に記録し、既存の開発者 ADC と store 経由の CLI で取得する。実 SendGrid には送らない。
- 任意ユーザーへのなりすましや Rules 迂回は行わない。許可ドメインは suffix `@verify.shokujii.test` のみ。

## 設定

| 項目 | 値 |
| --- | --- |
| Functions パラメータ | `VERIFICATION_TEST_OUTBOX_MODE=record_skip_send` |
| sandbox2603（正本） | GitHub Actions の `FUNCTIONS_ENV` に上記を追加して Functions を再デプロイする |
| sandbox2606 | 実施済み。2606〜2608 への追加変更はデータ構築の別 PR |
| 本番 / development（組織本流） | 未設定または `off` |

## 実装

- `functions/default/src/utils/verificationTestOutbox.ts`
- `scripts/pstack/fetch-test-pass-code.mjs`（事前に common / functions をビルド）
- `common/src/schemas/VerificationTestOutbox.ts`（Zod で保存・読取を検証）

## 1-6-1 停止箇所の分類（フェーズ1スコープ）

| 分類 | 内容 | 対応 |
| --- | --- | --- |
| メール配送・コード取得 | 実 SendGrid はエージェントが読めない | D-07 受け口 + ADC 認証済み CLI |
| 状態の復元 | 人の既存セッション再利用は未達 | 毎実行 `verification_run_id` で OTP フローを完走 |
| Google OAuth | 本スコープ外 | メール OTP ログインで代替 |

## レビュー修正後の境界

- 公開 OTP Callable とブラウザ用 API は廃止する。Functions 全体 deploy 時に旧 `fetchVerificationTestPassCode` の削除が必要。削除確認で CI が停止した場合、実行者が対象名を確認して既存デプロイ手順に従う。本番へは操作しない。既存 sandbox に残っている関数の削除完了までは公開経路が解消したと報告しない。
- 記録モードは登録済み sandbox2603 / 2606 / 2607 / 2608 の project ID に限定する。本流 development / 本番 / 未知 project は設定が有効でも off。2606〜2608 は selectable になるまで操作しない。
- CLI は ADC の既存 Firestore 読取権限を必要とし、新たな権限は付与しない。権限不足は停止理由として記録する。
- ローカル UI の新ブラウザ検証と、修正後 sandbox の実機検証は未完了。
