# 1-6-6 初期採用方式（2026-10-04）

## 採用

| 環境 | 方式 | 証明範囲 |
| --- | --- | --- |
| ローカル / sandbox（`VERIFICATION_TEST_OUTBOX_MODE=record_skip_send`） | 既存メールログイン + テスト受け口 + `fetchVerificationTestPassCode` | ログイン後の画面・カート操作（Google OAuth 自体は証明しない） |
| 本番 | 受け口 **off**（既定）。実 SendGrid 配送のまま | pstack 検証対象外 |

## 根拠

- Shokujii のユーザーログインは SendGrid 経由の独自 OTP（`requestEmailLogin` / `confirmEmailLogin`）であり、Auth Emulator の標準コード取得だけでは代替できない（[03_検証用ログインの検討.md](../03_検証用ログインの検討.md)）。
- D-07 に従い、通常検証では `@verify.shokujii.test` 宛の OTP を Firestore `verification_test_outbox` に記録し、Callable で取得する。実 SendGrid には送らない。
- 任意ユーザーへのなりすましや Rules 迂回は行わない。許可ドメインは suffix `@verify.shokujii.test` のみ。

## 設定

| 項目 | 値 |
| --- | --- |
| Functions パラメータ | `VERIFICATION_TEST_OUTBOX_MODE=record_skip_send` |
| sandbox2603（正本） | GitHub Actions の `FUNCTIONS_ENV` に上記を追加して Functions を再デプロイする |
| sandbox2606 | 実施済み。2606〜2608 への追加変更はデータ構築の別 PR |
| 本番 / development（組織本流） | 未設定または `off` |

## 実装

- `functions/default/src/verificationTest.ts`（`fetchVerificationTestPassCode`）
- `base/src/apis/verificationTest.ts`

## 1-6-1 停止箇所の分類（フェーズ1スコープ）

| 分類 | 内容 | 対応 |
| --- | --- | --- |
| メール配送・コード取得 | 実 SendGrid はエージェントが読めない | D-07 受け口 + `fetchVerificationTestPassCode` |
| 状態の復元 | 人の既存セッション再利用は未達 | 毎実行 `verification_run_id` で OTP フローを完走 |
| Google OAuth | 本スコープ外 | メール OTP ログインで代替 |
