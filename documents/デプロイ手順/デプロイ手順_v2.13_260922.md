## 実行順序の要点

```text
[0 ゲート] システム利用料 110 円の本番適用を確認
  → development の Deploy functions / index Enabled
  → 売切・限定食数・手数料・注文なし参加・オプション・フォーム・認証の E2E

[A 事前] 本番 orphan 棚卸し
  → SendGrid（48h はまだ触らない。未読・新着 ASM・督促テンプレの存在確認）
  → production の SUPPORT_ENV と FIREBASERC の support target
  → 本番 support_user_ids

[B 当日]
  Analytics → メンテ ON → Firestore バックアップ
  → ⚠️ SendGrid 2 テンプレを 48h 表記に更新
  → release PR マージ → tag → push main production
  → CI: firestore(index → rules) → functions（売切 Trigger の failure policy）
       → hosting（user / partner / enterprise / terms / support）
  → 売切・残数・フォームの index が Enabled になるまで該当機能を判定に使わない

[C 後]
  売切 / 限定食数 / 手数料 / 注文なし参加 / 認証 / SEO → メンテ OFF
  support はバイパスされるので、公開判断は GATE-12 で別にする
```

## トラブルシュート

### `Deploy functions` が failure policy で abort する

**症状**: `Pass the --force option to deploy functions with a failure policy`。

**原因**: `onPartnerMenuSoldOutChanged` が本番初出（`retry: true`）。

**対処**: B-5 のあと `Deploy functions` を re-run。以降は再発しない。CI は #2356 で名前指定 `--force` する想定。

### `Deploy functions` が `Command aborted` で失敗する

**症状**: `The following functions are found in your project but do not exist in your local source` に続いて `Command aborted.`。

**原因**: `--force` 廃止後、`index.ts` に export の無い関数が GCP 上に残っていると CLI が削除確認を求め、非対話の Actions では abort する。

**対処**: A-3 の手順で残存関数を削除して再実行する。

### 売切が参加者に反映されない

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| ずっと変わらない | Trigger 未デプロイ | `functions:list` で存在確認 |
| failed-precondition | index building | Enabled まで待つ |
| 下書き/申請中だけ変わらない | 仕様 | 承認時スナップショットで反映 |

### 残数が出ない / 定数クエリエラー

**原因**: `member_orders` の `event_id + menu_id + status` index が building。

**対処**: Enabled 待ち。注文確定のサーバー判定も同じ index を使う。

### `Deploy user` が communitylist rewrite で 400

**原因**: `handleCommunityListSeoRequest` 未デプロイのまま Hosting が先。

**対処**: functions 完了後に `Deploy user` を re-run（v2.12 の sitemap と同じ）。

### 店舗メニューが保存できない

**原因**: Rules がパートナー配下メニューの直接書き込みを拒否している。保存は `savePartnerMenu` などの Callable。

**対処**: `Deploy functions` が success であることと、partner を再読み込みしてから保存する。Callable が未デプロイのまま Rules だけ新しいと、再読み込みしても保存できない。

### フォーム回答や support 一覧が failed-precondition

**原因**: A-4 の index が building。

**対処**: Enabled まで待つ。フォーム無しの通常注文は、この index がなくても確定できる。

### 新着イベントメールがコミュニティメンバーに届かない

**原因**: Unsubscribe Group `36042` が本番 SendGrid に無い、またはテンプレにグループ配信停止リンクが無い。コードはグループ未設定のとき送信しない。

**対処**: A-5。注文完了メールとは別。

### チャット未読メールがメンテ直後に届かない

**原因**: 仕様。9:00–12:00 または 18:00–23:00（JST）、最終投稿から 1 時間、前回送信から 72 時間。

**対処**: `chatUnreadMail` が list にあり、index が Enabled ならリリース判定は Pass。実メールは窓の中で CHAT-05。

### 予約メールの期限が 3 日のまま

**原因**: SendGrid テンプレ未更新。

**対処**: B-2。コードロールバックでは直らない。

### PF プロフィールから注文が消える

v2.13 では `0046` を再実行しない。もし消えたら **v2.12 の `enterprise_id: null` 欠落**を疑う（コードロールバックだけでは直らない）。

- **`development` はロールバックしない**
- Rules も v2.12 に戻す。Functions だけ戻すと、店舗メニューの直接書き込みが拒否されたまま保存できない
- `limit_per_event` / `user_tags` / `selected_options` / `item_type` / フォーム定義は残ってよい。v2.12 は未知フィールドを落とす
- 「食事は持参」の予約メニュー（`menu_id` が参加専用）が `is_selected: true` のままだと、旧画面では 0 円の通常メニューに見える。戻すときはその選択を外す
- すでに作られた Checkout のシステム利用料は Stripe 上の金額のまま。コードを戻しても徴収済みは返らない
- support サイトは v2.12 の workflow に含まれない。ロールバック後も新バンドルが残る。止めるなら Hosting を止める判断が別途いる
- SendGrid を 48h にしていた場合、ロールバックするならテンプレも 72h に戻すか、コードの 48h と揃えるか判断する
- 削除しない: 新規 index（残っても害は小さい）
