## 1. 概要

### 1.1 機能の目的

イベントグループチャットに未読があるとき、アプリを開いていない参加者へ **メールで「チャットがあります」と気づかせる**。メッセージごとの即時メールは送らず、回数と時間帯を制限してうざさを抑える。

### 1.2 主要な機能

- 未読が残っているユーザーへ、SendGrid でリマインドメールを送る
- 送信時間帯は **午前 9:00–12:00** と **夕方 18:00–23:00**（JST）。ユーザー全体で前回送信から **72 時間以上**空ける
- **23:00 以降は送らず、翌朝 9:00 以降**に持ち越す
- 各ルームの **最後の投稿から 1 時間**経つまで送らない。投稿が続けば待ち時間は延びる。ルームを開いて既読にした人には送らない
- チャットごとに一度通知したら、**そのチャットを読むまで追加通知しない**。新しい挨拶・投稿が増えても再開せず、既読後の新しい未読で再び対象になる

### 1.3 対象ユーザー

- `user` アプリのログイン済み一般ユーザー
- `users_personal_information.user_email` が空でない人
- 対象ルームの `chat_memberships` があり、`is_active === true` かつ `unread_count > 0` の人

**対象外**

- `partner` / 飲食店向けメール
- メール未登録ユーザー（アプリ内未読バッジのみ）
- 削除済みユーザー（`users.is_deleted`）
- 停止済みエンタープライズ利用者（`users.enterprise_id` があり、Enterprise または EnterpriseMember が無効）
- 送信者本人（未読加算されないため、本機能の対象にならない）

### 1.4 他チャネルとの役割

| チャネル | 役割 | 時期 |
| --- | --- | --- |
| アプリ内未読バッジ | 開いているときの気づき | 既存（v1） |
| **本メール** | アプリ外の気づき（最短 72 時間間隔・既読まで追加通知なし） | **#2354 Phase 1** |
| FCM プッシュ | ロック画面の即時通知 | 後続（`02_プッシュ通知.md`） |
| レター | 管理者の公式・一方向連絡 | 既存。本機能と混ぜない |

メールはチャットの存在に気づいてもらうためのまとめ通知とする。挨拶促進によって投稿が増えても、見ていない参加者に通知を繰り返さない。閲覧する人についても、全ルームを通じて最短 72 時間間隔に抑える。

## 2. ねらい

### 2.1 ビジネス目標

- チャット返信率を上げ、イベント当日の連絡がスレッド内で完結するようにする
- 「送っても誰も見ない」を減らし、グループチャットを使ってもらう

### 2.2 ユーザー価値

- アプリを常時開いていなくても、未読があることに気づける
- 連投で受信箱が埋まらない（ユーザー全体で最短 72 時間間隔、通知したチャットは既読まで停止）
- 深夜・早朝には届かない

### 2.3 成功指標（KPI）

- メール送信成功数 / 未読ユーザー数（枠内）
- 送信後 24 時間以内のチャット再訪率（リンククリックまたは `last_read_at` 更新）
- 送信後 24 時間以内の返信率
- 配信停止率（SendGrid ASM）
- 送信失敗率（メール空・無効アドレス・SendGrid エラー）

### 2.4 リスクと UX

| リスク | 対策 |
| --- | --- |
| 毎回メールで離脱 | 最短 72 時間間隔・最後の投稿から 1 時間待ち・チャットを読むまで追加通知しない |
| 別イベントから通知が続く | 72 時間の制限はユーザー単位。新しく参加した別イベントも次の送信可能時刻まで待つ |
| 深夜送信 | 23:00–9:00 は送らない |
| 通信の秘密・個人情報 | 本文は一覧と同じプレビュー（最大 100 文字）。全文は載せない |
| 読まない人への追いかけ | membership の `last_unread_mail_sent_at` と `last_read_at` を比較し、通知後に読んでいないルームを本文・件数からも除外する |

## 3. 前提条件

### 3.1 技術的前提条件

- チャット v1 以上がデプロイ済み（`onChatMessageCreated` による `unread_count` / `last_message_*`）
- 表示中ルームは即 `markAsRead`（開いている相手には未読が残らない）
- SendGrid Dynamic Templates と `functions/default` の既存送信経路（`utils/sendgrid.ts` / `sendgridBulk.ts`）
- 宛先は `getUserPersonalInformation` の `user_email`（既存注文完了メールと同じ）
- 日時は **luxon + `Asia/Tokyo`**。Scheduled の判定は `context.scheduleTime` を使う（`new Date()` 禁止）
- DB 操作は store 経由。`xxxRef` は `withConverter` 付き

### 3.2 ビジネス的前提条件

- 電気通信事業届出はチャット v1 で提出済み。メールにプレビューを載せる場合は、届出書類・プライバシーポリシーの追記 / 変更届要否を管轄へ確認する（[`03_電気通信事業届出準備.md`](./03_電気通信事業届出準備.md)）
- Phase 1 にアプリ内の通知 ON/OFF は置かない。配信停止はメールフッタの Unsubscribe（SendGrid ASM）

### 3.3 依存関係

| 依存 | 用途 |
| --- | --- |
| `users/{uid}/chat_memberships` | 未読・プレビュー・`is_active` |
| `chat_rooms` | ルーム名（`title`）。無ければ event / community を join |
| `users_personal_information` | 宛先メール |
| `shouldIncrementMembershipUnread` と同条件の未読 | システムメッセージ・送信者は対象外 |

## 5. 技術仕様・データ構造設計

### 5.1 送信時間帯・間隔（確定）

タイムゾーンは **Asia/Tokyo**。時間帯の境界は半開区間。

| 時間帯 | 時刻 |
| --- | --- |
| `morning` | **09:00 以上 12:00 未満** |
| `evening` | **18:00 以上 23:00 未満** |
| 送信停止 | 12:00–18:00 および 23:00–翌 09:00 |

ユーザー全体で **前回送信から 72 時間以上**空ける。カレンダー日付での「3 日後」ではなく経過時間で判定する。72 時間が経っても、送信時間帯・ルームごとの条件を満たすまで送らない。別イベントの初回通知にも同じ間隔を適用する。

### 5.2 送信条件

**以下を満たすルームだけを通知対象にする。**

| # | 条件 | 備考 |
| --- | --- | --- |
| 1 | 現在時刻が `morning` または `evening` | 枠外はクエリせず終了 |
| 2 | ユーザーの前回送信から 72 時間以上、または未送信 | 全ルーム共通の `last_sent_at` で判定 |
| 3 | `is_active === true` かつ `unread_count > 0` | 送信直前にトランザクション内で membership を再取得する |
| 4 | `last_message_at` があり、`last_read_at` がある場合はそれより後 | 既読時刻以前の投稿や実行遅延による古い未読判定を除く |
| 5 | `last_unread_mail_sent_at` がない、または `last_read_at > last_unread_mail_sent_at` | このチャットの前回通知後に既読にしていること。別チャットの閲覧では再開しない |
| 6 | `last_message_at <= now - 1時間` | 最後の投稿から 1 時間待つ。古い別ルームに便乗して新着直後のルームを載せない |
| 7 | 有効な `user_email` があり、削除・停止済みユーザーではない | 従来の対象条件を維持 |

未読数が増えても条件 5 は解除しない。既読時には既存どおり `last_read_at` と `unread_count` を更新するだけで、通知時刻の削除やフラグのリセットは不要。

`last_sent_at` はユーザー全体の送信間隔にだけ使う。別ルームの前回メールより古い投稿でも、そのルームが未通知なら対象にできる。

対象ルームを `last_message_at` 降順で最大 5 件に絞り、この 5 件だけを件名・本文・件数・CTA と通知済み記録の対象にする。停止中のルームや 1 時間未満のルームは載せない。6 件目以降は通知済みにせず、次回以降に再判定する。

送信者本人やシステムメッセージのみのルームは未読が加算されないため対象外。送信取り消し時に `unread_count` を減らさない既存仕様は維持する。

### 5.3 動きの例

以下はメール未停止・有効なルームを前提とする。

| 状況 | 結果 |
| --- | --- |
| 初回の投稿が 10:00、開かない | 11:00 以降のジョブで通知 |
| 初回の投稿が 11:30 | 1 時間後は時間帯外 → 18:00 以降 |
| 初回の投稿が 22:30 | 1 時間後は時間帯外 → 翌朝 09:00 以降 |
| 10:00 の投稿後、10:40 に追加投稿 | 最後の投稿から 1 時間となる 11:40 以降 |
| 通知後、開かずに挨拶が増える | 72 時間経っても追加通知しない |
| 通知後にそのチャットを読み、新しい未読が発生 | 前回メールから 72 時間以上かつ最後の投稿から 1 時間以上で再通知 |
| 別チャットだけを読む | 元のチャットの停止は解除しない |
| 別イベントに未通知のチャットがある | ユーザー全体の 72 時間間隔を満たしてから通知 |
| 72 時間が経ったが未読がない | 送らない |

### 5.4 Firestore

#### 5.4.1 membership に通知時刻を追加

```
/users/{userId}/chat_memberships/{roomId}
/chat_rooms/{roomId}
/users_personal_information/{userId}
```

未読判定は membership を読む。メッセージ本文は読まない。

`chat_memberships/{roomId}` に **`last_unread_mail_sent_at?: Timestamp`** を追加する。このユーザーへこのチャットを最後にメール通知した時刻。未設定は未通知として扱う。Functions のみ更新し、既読化では変更しない。

#### 5.4.2 既存: ユーザー全体の送信状態

```
/users/{userId}/notification_states/chat_unread_mail
```

ドキュメント ID は固定の `chat_unread_mail`。クライアントは read/write しない。Functions（Admin）のみ。

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `last_sent_at` | Timestamp | ✓ | ユーザー全体の直近の送信時刻。72 時間間隔を判定する。送信権の確保時に仮更新し、成功時に維持、失敗時に戻す |

`last_slot_id` / `last_sent_room_ids` / `created_at` / `updated_at` は持たない。`users/{uid}` 本体にも足さない。

アカウント削除（`deleteUserAccount`）でこのドキュメントを削除する。

#### 5.4.3 Zod（実装時）

既存の `common/src/schemas/ChatUnreadMailState.ts` と `ChatMembership.ts` を使う。

- 通知状態のフィールドは既存の `last_sent_at` のみ。membership に optional な `last_unread_mail_sent_at` を追加する
- DbSchema: `TimestampSchema`
- AppSchema: `EpochMillisSchema`

### 5.5 インデックス

`chat_memberships` の collection group クエリ用。

```json
{
  "collectionGroup": "chat_memberships",
  "queryScope": "COLLECTION_GROUP",
  "fields": [
    { "fieldPath": "is_active", "order": "ASCENDING" },
    { "fieldPath": "unread_count", "order": "ASCENDING" }
  ]
}
```

クエリ: `is_active == true` かつ `unread_count > 0`。親ドキュメント ID が `userId`。

### 5.6 Security Rules

```
match /users/{user_id}/notification_states/{stateId} {
  allow read, write: if false;
}
```

書き込みは Admin SDK のみ。クライアント改ざんによる再送・抑止回避を防ぐ。membership の既存 Rules も更新可能フィールドを既読用の 3 項目に限定しており、`last_unread_mail_sent_at` の追加・更新・削除は許可しない。Rules の権限拡張は不要。

### 5.7 Functions

#### 5.7.1 Scheduled（本体）

| 項目 | 内容 |
| --- | --- |
| 関数名 | `chatUnreadMail`（lowerCamelCase） |
| 種別 | `onSchedule` |
| schedule | `*/5 * * * *`（5 分ごと） |
| timeZone | `Asia/Tokyo` |
| region | `asia-northeast1` |
| secrets | `SENDGRID_API_KEY` |
| maxInstances / concurrency | 各 `1`（同一インスタンスへの同時実行を含め、ジョブの重なりを抑える） |
| 配置 | `functions/default/src/chatUnreadMail.ts` |
| export | `functions/default/src/index.ts` に import / export（deploy yml 手書き不要） |

`pollingTask`（1 分・既存メール多数）には載せない。時間帯判定・1 時間待ち・72 時間間隔をこのジョブ内で行う。

枠外（12:00–18:00 および 23:00–09:00）は **クエリせず return** する。

#### 5.7.2 処理フロー

1. `DateTime.fromISO(context.scheduleTime, { zone: 'Asia/Tokyo' })` で `now` と時間帯を決める。時間帯外なら終了
2. collection group で未読かつ active な membership を取得し、`userId` でグループ化する（store 関数）
3. ユーザーごとに削除・メール空・エンタープライズ停止を確認し、該当すればスキップ
4. store のトランザクションで通知状態を読む。72 時間未満なら終了。それ以外は候補 membership を再取得して §5.2 を評価する（すべての read を write より先に行う）
5. 本文に載せる最大 5 ルームを選び、ユーザーの `last_sent_at` と選んだ membership の `last_unread_mail_sent_at` を同時に `now` に更新して送信権を確保する。確保前の通知時刻と対象 membership を呼び出し元へ返す
6. 確保したルームだけで件名・本文・リンクを組み立てて SendGrid 送信。本文を組み立てられない場合や送信失敗時は確保を戻す
7. 復元もトランザクション内で最新状態を取得する。自分が確保した送信時刻と一致する場合のみ、全体とルームの通知時刻を戻す。既読時刻・未読数・新着プレビューなどは最新値を維持し、削除された membership は復活させない。初回なら通知状態ドキュメント・ルームの通知時刻フィールドを除去する。復元失敗は最大 3 回試行して記録する
8. 送信成功後は確保した状態を維持する。成功後の追加書き込みはしない
9. 個別失敗は他ユーザーを止めない（`Promise.allSettled`）。ログは `createModuleLogger`

Firestore の確保と SendGrid の送信は単一トランザクションにはできないため、確保後のプロセス終了や応答不明時の厳密な一度だけの配信は保証しない（既存の確保・失敗時復元方式を継続）。

#### 5.7.3 内部モジュール（案）

| モジュール | 役割 |
| --- | --- |
| `resolveChatMailSlot(now)` | `morning` / `evening` / `null` |
| `shouldSendChatUnreadMail(...)` | §5.2 の純関数。Vitest 対象 |
| `buildChatUnreadMailPayload(...)` | 件名・変数 |
| `getChatUrlForUser(userId, roomId)` | host 解決 |

`onChatMessageCreated` から直接 SendGrid は呼ばない（即時メールにしない）。

### 7.3 対象外（当面）

- メッセージごとの即時メール
- メンション限定（メンション未実装）
- partner アプリ
- 12:00 や 8:00 開始の追加枠
- 主催者専用の「遅刻連絡」メール（本機能の目的にしない）

## 8. 注意事項

### 8.1 既存システムへの影響

- **DB**: 既存 `notification_states` を再利用し、membership に optional な通知時刻を追加する。`users` 本体は変更しない
- **Functions**: 5 分周期の新規 Scheduled。`onChatMessageCreated` のレイテンシには影響しない
- **メール**: 既存の注文・新着イベント（10:00 / 10:15 帯）と枠が重なり得る。件名でチャットと判別できるようにする
- **費用**: ユーザーあたり最短 72 時間間隔。通知後に読んでいないルームは停止する。時間帯外はクエリしない

### 8.2 セキュリティ

- 状態ドキュメントはクライアント不可
- 送信は Functions + Admin SDK のみ
- メール本文にメッセージ全文・data payload 相当の本文を載せない
- リンク先は既存 Firestore Rules でメンバー以外は読めない
- トークンや個人情報をログに出さない

### 8.3 運用

- Cloud Logging で送信数・スキップ理由（時間帯外 / 1 時間待ち / 72 時間未満 / 通知後の既読待ち / メール空）を出す
- SendGrid 失敗は Error Reporting。確保の復元に成功すれば、次のジョブで送信条件を再判定する
- テンプレート ID / ASM グループ ID は記入済み
- 本番前に届出・プライバシーポリシーを確認する

### 8.4 テスト方針

| 対象 | 内容 |
| --- | --- |
| 純関数 | 時間帯判定、1 時間・72 時間の境界、既読まで停止・既読後再開、ルーム単位の独立性 |
| Functions | メール空・削除ユーザー・inactive・未読 0 を送らない。確保後の対象だけを本文に載せる。SendGrid mock・送信失敗時復元 |
| Store | 送信前の既読再取得、最大 5 件、失敗時に既読・新着を維持、退会済み membership を復活させない |
| Rules | `notification_states` の client write 拒否、membership 通知時刻の改ざん拒否、通常の既読化を許可 |
| 実機 | §7.1 の E2E |

境界の固定時刻は luxon で `2026-09-22T11:50:00+09:00` のように明示する。
