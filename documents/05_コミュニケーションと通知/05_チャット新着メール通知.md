## 1. 概要

### 1.1 機能の目的

イベントグループチャットに未読があるとき、アプリを開いていない参加者へ **メールで「チャットがあります」と気づかせる**。メッセージごとの即時メールは送らず、回数と時間帯を制限してうざさを抑える。

### 1.2 主要な機能

- 未読が残っているユーザーへ、SendGrid でリマインドメールを送る
- 送信枠は **午前 9:00–12:00** と **夕方 18:00–23:00**（JST）。各枠 **最大 1 通**
- **23:00 以降は送らず、翌朝 9:00 以降**に持ち越す
- 未読のまま **15 分**経つまで送らない。ルームを開いて既読にした人には送らない
- 前回送信より後に **新しい未読が無い**ときは再送しない

### 1.3 対象ユーザー

- `user` アプリのログイン済み一般ユーザー
- `users_personal_information.user_email` が空でない人
- 対象ルームの `chat_memberships` があり、`is_active === true` かつ `unread_count > 0` の人

**対象外**

- `partner` / 飲食店向けメール
- メール未登録ユーザー（アプリ内未読バッジのみ）
- 削除済みユーザー（`users.is_deleted`）
- 停止済みエンタープライズ利用者（`users.enterprise_id` があり、Enterprise または EnterpriseMember が無効）
- 送信者本人（未読加算されないため、本機能の対象にならない）

### 1.4 他チャネルとの役割

| チャネル | 役割 | 時期 |
| --- | --- | --- |
| アプリ内未読バッジ | 開いているときの気づき | 既存（v1） |
| **本メール** | アプリ外の気づき（1 日最大 2 通） | **#2354 Phase 1** |
| FCM プッシュ | ロック画面の即時通知 | 後続（`02_プッシュ通知.md`） |
| レター | 管理者の公式・一方向連絡 | 既存。本機能と混ぜない |

他 SNS の整理: Slack / Discord / Facebook / X も、グループ発言をメールで毎回は送らない。メールは見逃し用にまとめ、即時はプッシュが主である。LINE のトークにメールは無い。本書は Slack の「まとめて送る」を、設定なし・1 日最大 2 通に寄せた版とする。

## 2. ねらい

### 2.1 ビジネス目標

- チャット返信率を上げ、イベント当日の連絡がスレッド内で完結するようにする
- 「送っても誰も見ない」を減らし、グループチャットを使ってもらう

### 2.2 ユーザー価値

- アプリを常時開いていなくても、未読があることに気づける
- 連投で受信箱が埋まらない（枠あたり 1 通、1 日最大 2 通）
- 深夜・早朝には届かない

### 2.3 成功指標（KPI）

- メール送信成功数 / 未読ユーザー数（枠内）
- 送信後 24 時間以内のチャット再訪率（リンククリックまたは `last_read_at` 更新）
- 送信後 24 時間以内の返信率
- 配信停止率（SendGrid ASM）
- 送信失敗率（メール空・無効アドレス・SendGrid エラー）

### 2.4 リスクと UX

| リスク | 対策 |
| --- | --- |
| 毎回メールで離脱 | 枠制限・15 分待ち・新しい未読が無いと再送しない |
| 11:45 の直後に 12:00 | 枠を隣り合わせない。保険で前回送信から 4 時間未満は送らない |
| 深夜送信 | 23:00–9:00 は送らない |
| 通信の秘密・個人情報 | 本文は一覧と同じプレビュー（最大 100 文字）。全文は載せない |
| 同じ未読の繰り返し | `last_message_at > last_sent_at` の未読が無いと送らない |

## 3. 前提条件

### 3.1 技術的前提条件

- チャット v1 以上がデプロイ済み（`onChatMessageCreated` による `unread_count` / `last_message_*`）
- 表示中ルームは即 `markAsRead`（開いている相手には未読が残らない）
- SendGrid Dynamic Templates と `functions/default` の既存送信経路（`utils/sendgrid.ts` / `sendgridBulk.ts`）
- 宛先は `getUserPersonalInformation` の `user_email`（既存注文完了メールと同じ）
- 日時は **luxon + `Asia/Tokyo`**。Scheduled の判定は `context.scheduleTime` を使う（`new Date()` 禁止）
- DB 操作は store 経由。`xxxRef` は `withConverter` 付き

### 3.2 ビジネス的前提条件

- 電気通信事業届出はチャット v1 で提出済み。メールにプレビューを載せる場合は、届出書類・プライバシーポリシーの追記 / 変更届要否を管轄へ確認する（[`03_電気通信事業届出準備.md`](./03_電気通信事業届出準備.md)）
- Phase 1 にアプリ内の通知 ON/OFF は置かない。配信停止はメールフッタの Unsubscribe（SendGrid ASM）

### 3.3 依存関係

| 依存 | 用途 |
| --- | --- |
| `users/{uid}/chat_memberships` | 未読・プレビュー・`is_active` |
| `chat_rooms` | ルーム名（`title`）。無ければ event / community を join |
| `users_personal_information` | 宛先メール |
| `shouldIncrementMembershipUnread` と同条件の未読 | システムメッセージ・送信者は対象外 |
| `EVENT_HOST` / enterprise host | チャット URL（`/chat/{roomId}`） |

## 4. 送信仕様（画面の代わり）

アプリ内の新規画面は Phase 1 では作らない。表示面は **SendGrid テンプレート**のみ。

### 4.1 件名

| 未読ルーム数 | 件名案 |
| --- | --- |
| 1 | `{ルーム名}に未読のチャットがあります` |
| 2 以上 | `{件数}件のチャットに未読があります` |

ルーム名はイベントチャットならイベント名（`chat_rooms.title` または events join）。取れないときは `グループチャット`。

### 4.2 本文

Slack の「チャットがあります」に寄せ、全文は載せない。

| 要素 | 内容 |
| --- | --- |
| リード | 未読のメッセージがあります。チャットを開いて返信できます。 |
| ルーム行（最大 5） | ルーム名、未読数、`last_message_preview`（既存一覧と同じ。最大 100 文字） |
| 6 件以上 | 「他 N 件のチャットに未読があります」 |
| CTA | 「チャットを開く」。未読 1 件なら `/chat/{roomId}`、複数なら `/chat`（一覧） |
| フッタ | 配信停止リンク（ASM） |

画像のみのプレビューは既存どおり `画像を送信しました`（`buildMessagePreview` / membership の `last_message_preview`）。

### 4.3 リンク

- PF: `https://{EVENT_HOST}/chat` または `/chat/{roomId}`（`user/src/router/utils.ts` の `getChatPath` と同じ）
- エンタープライズ: 既存の `resolveAppHostForCommunity` / `user.enterprise_id` に合わせた host。解決できない場合は **送らない**（誤 host に出さない）
- 未ログインで開いた場合は、既存チャット画面のログイン復帰に任せる

### 4.4 テンプレート変数（案）

| 変数 | 型 | 説明 |

| `unread_room_count` | number | 未読ルーム数 |
| `rooms` | array | `{ room_name, unread_count, preview, chat_url }`（最大 5） |
| `more_room_count` | number | 6 件目以降の件数。0 なら非表示 |
| `cta_url` | string | 主 CTA |

| 項目 | Phase 1 |

## 5. 技術仕様・データ構造設計

### 5.1 送信枠（確定）

タイムゾーンは **Asia/Tokyo**。境界は半開区間。

| 枠 ID | 時刻 | 上限 |
| --- | --- | --- |
| `morning` | **09:00 以上 12:00 未満** | 1 通 |
| `evening` | **18:00 以上 23:00 未満** | 1 通 |
| （送信停止） | **23:00 以上 翌 09:00 未満** | 送らない。翌朝 `morning` に持ち越し |

1 日の上限は枠の定義により **最大 2 通**。12:00–18:00 も送らない（昼の未読は 18:00 以降）。

保険: **前回送信から 4 時間未満は送らない**。枠が 6 時間空いているため、11:45 の次は最早 18:00 になる。

### 5.2 送信条件

**すべて満たしたときだけ送る。**

| # | 条件 | 備考 |
| --- | --- | --- |
| 1 | 現在時刻が `morning` または `evening` | 枠外はジョブ全体を no-op してよい |
| 2 | 対象 membership が 1 件以上 | `is_active === true` かつ `unread_count > 0` |
| 3 | 送る未読が、未読のまま **15 分以上** | 初回は未読のいずれかが `last_message_at <= now - 15分`。再送は `last_message_at > last_sent_at` の未読のうち 15 分以上のものが 1 件以上。古い未読の 15 分待ちでは新しい未読をすぐ送らない |
| 4 | 前回送信より後に新しい未読がある | 初回は `last_sent_at` 無しで可。再送は `last_message_at > last_sent_at` の未読があること |
| 5 | 当該カレンダー日（JST）の当該枠で未送信 | `last_sent_at` が今と同じ枠に入っていれば送らない |
| 6 | 前回送信から 4 時間以上、または未送信 | |
| 7 | 有効な `user_email` がある | trim 後空ならスキップ |
| 8 | ユーザーが削除されていない | |

**送らない例（既存チャット仕様と一致）**

- `message_type === 'system'` のみ（未読が乗らない）
- 送信者本人
- `is_active === false`（終了・アーカイブ）
- 表示中で即既読済み（`unread_count === 0`）

送信取り消し後も `unread_count` は減らさない（チャット正本どおり）。未読が残っていれば本メールの対象になり得る。プレビューは再計算後の `last_message_preview` を使う。

### 5.3 動きの例

前提: 15 分待ちを満たしている。

| 状況 | 結果 |
| --- | --- |
| 昨夜の未読が残っている | 09:00 以降の最初のジョブで `morning` 1 通 |
| 10:00 に未読、開かない | 10:15 以降に `morning` 1 通。次は 18:00 以降かつ新しい未読があるとき |
| 11:50 に未読 | 15 分後は 12:05 で枠外 → **18:00** まで待つ（12:00 には送らない） |
| 13:00 の未読 | **18:00** 以降 |
| 22:40 の未読 | 22:55 は `evening` 内なので送る |
| 22:50 の未読 | 15 分後は 23:05 で停止帯 → **翌朝 09:00** |
| 午前に送り、その後新しい発言が無い | 夕方は送らない |
| 午前に送り、夕方に新しい未読 | `evening` でもう 1 通 |

### 5.4 Firestore

#### 5.4.1 既存（変更なし）

```
/users/{userId}/chat_memberships/{roomId}
/chat_rooms/{roomId}
/users_personal_information/{userId}
```

未読判定は membership を読む。メッセージ本文は読まない。

#### 5.4.2 新規: 送信状態

```
/users/{userId}/notification_states/chat_unread_mail
```

ドキュメント ID は固定の `chat_unread_mail`。クライアントは read/write しない。Functions（Admin）のみ。

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `last_sent_at` | Timestamp | ✓ | 直近の送信成功時刻。同一枠判定・新しい未読・4 時間間隔はすべてこの 1 本から算出する |

`last_slot_id` / `last_sent_room_ids` / `created_at` / `updated_at` は持たない。`users/{uid}` 本体にも足さない。

アカウント削除（`deleteUserAccount`）でこのドキュメントを削除する。

#### 5.4.3 Zod（実装時）

`common/src/schemas/ChatUnreadMailState.ts` を新設する。

- フィールドは `last_sent_at` のみ
- DbSchema: `TimestampSchema`
- AppSchema: `EpochMillisSchema`

### 5.5 インデックス

`chat_memberships` の collection group クエリ用。

```json
{
  "collectionGroup": "chat_memberships",
  "queryScope": "COLLECTION_GROUP",
  "fields": [
    { "fieldPath": "is_active", "order": "ASCENDING" },
    { "fieldPath": "unread_count", "order": "ASCENDING" }
  ]
}
```

クエリ: `is_active == true` かつ `unread_count > 0`。親ドキュメント ID が `userId`。

### 5.6 Security Rules

```
match /users/{user_id}/notification_states/{stateId} {
  allow read, write: if false;
}
```

書き込みは Admin SDK のみ。クライアント改ざんによる再送・抑止回避を防ぐ。

### 5.7 Functions

#### 5.7.1 Scheduled（本体）

| 項目 | 内容 |
| --- | --- |
| 関数名 | `chatUnreadMail`（lowerCamelCase） |
| 種別 | `onSchedule` |
| schedule | `*/5 * * * *`（5 分ごと） |
| timeZone | `Asia/Tokyo` |
| region | `asia-northeast1` |
| secrets | `SENDGRID_API_KEY` |
| maxInstances / concurrency | 各 `1`（同一インスタンスへの同時実行を含め、ジョブの重なりを抑える） |
| 配置 | `functions/default/src/chatUnreadMail.ts` |
| export | `functions/default/src/index.ts` に import / export（deploy yml 手書き不要） |

`pollingTask`（1 分・既存メール多数）には載せない。枠判定と 15 分待ちをこのジョブ内で行う。

枠外（12:00–18:00 および 23:00–09:00）は **クエリせず return** する。

#### 5.7.2 処理フロー

1. `DateTime.fromISO(context.scheduleTime, { zone: 'Asia/Tokyo' })` で `now` と枠 ID を決める。枠外なら終了
2. collection group で未読かつ active な membership を取得する（store 関数）
3. `userId` でグループ化する
4. ユーザーごとに削除・メール空・エンタープライズ停止を見る。該当すればスキップ
5. トランザクションで §5.2 を再評価し、送る場合だけ `last_sent_at` を `now` に書いて送信権を取る。取れなければスキップ
6. 載せるルームを `last_message_at` 降順で最大 5 件にし、ルーム名と `cta_url` を組み立てる。組み立てに失敗したら送信権を戻す
7. SendGrid 送信。失敗時は送信権を戻す（初回ならドキュメント削除、再送なら以前の `last_sent_at`）。戻しは数回再試行する
8. 送信成功後は `last_sent_at` を維持する。成功後の追加書き込みはしない（書き込み失敗による同一枠の再送を避ける）
9. 個別失敗は他ユーザーを止めない（`Promise.allSettled`）。ログは `createModuleLogger`

#### 5.7.3 内部モジュール（案）

| モジュール | 役割 |
| --- | --- |
| `resolveChatMailSlot(now)` | `morning` / `evening` / `null` |
| `shouldSendChatUnreadMail(...)` | §5.2 の純関数。Vitest 対象 |
| `buildChatUnreadMailPayload(...)` | 件名・変数 |
| `getChatUrlForUser(userId, roomId)` | host 解決 |

`onChatMessageCreated` から直接 SendGrid は呼ばない（即時メールにしない）。

### 5.8 フロントエンド

Phase 1 は変更なし。許可ダイアログも設定トグルも無い。

## 8. 注意事項

### 8.1 既存システムへの影響

- **DB**: `notification_states` サブコレクション追加。`users` / membership スキーマは変更しない
- **Functions**: 5 分周期の新規 Scheduled。`onChatMessageCreated` のレイテンシには影響しない
- **メール**: 既存の注文・新着イベント（10:00 / 10:15 帯）と枠が重なり得る。件名でチャットと判別できるようにする
- **費用**: 未読ユーザー × 最大 2 通/日。枠外はクエリしない

### 8.2 セキュリティ

- 状態ドキュメントはクライアント不可
- 送信は Functions + Admin SDK のみ
- メール本文にメッセージ全文・data payload 相当の本文を載せない
- リンク先は既存 Firestore Rules でメンバー以外は読めない
- トークンや個人情報をログに出さない

### 8.3 運用

- Cloud Logging で送信数・スキップ理由（枠外 / デバウンス / 同一枠済 / 新規未読なし / メール空）を出す
- SendGrid 失敗は Error Reporting。状態未確定のため同一枠で再試行される
- テンプレート ID と ASM ID を本書に実装後追記する
- 本番前に届出・プライバシーポリシーを確認する

### 8.4 テスト方針

| 対象 | 内容 |
| --- | --- |
| 純関数 | 枠判定、15 分、4 時間、同一枠、新しい未読、JST 日付またぎ |
| Functions | メール空・削除ユーザー・inactive・未読 0 を送らない。SendGrid mock |
| Rules | `notification_states` の client write 拒否 |
| 実機 | §7.1 の E2E |

境界の固定時刻は luxon で `2026-09-22T11:50:00+09:00` のように明示する。
