# イートイン

- **ステータス**: 仕様（未実装）。業態 `eatin` は [03_複数店舗・複数メニューリスト.md](./03_複数店舗・複数メニューリスト.md) Phase 2。部屋は未採用
- **関連仕様書**: [03_複数店舗・複数メニューリスト.md](./03_複数店舗・複数メニューリスト.md) / [05_テイクアウト.md](./05_テイクアウト.md)

## 1. 概要

### 1.1 機能の目的

店舗のイートイン営業を、デリバリーとは別の業態として時間帯とメニューリストで設定する。

### 1.2 主要な機能

- 業態種別 `eatin`
- 注文期限は提供開始の何分前
- 最小注文金額と 1 注文あたり最大個数は任意
- 部屋・席数・最低保証料金は、予約台帳と請求先が決まるまでスキーマに入れない

### 1.3 対象ユーザー

- **飲食店**: イートインの時間帯とメニューを設定する
- **主催者・参加者**: その時間帯のメニューをイベントで注文する

### 1.4 スコープ外

- 部屋一覧、部屋写真、最小席数、最大席数、部屋別最低保証料金
- 部屋の予約カレンダーとダブルブッキング防止
- 店舗主催フラグ。誰がイベントを作れるかは業態の属性にしない
- 着席管理、テーブルステータス

## 2. ねらい

### 2.1 ビジネス目標

- 店内提供と配達で、メニューと締切を分けられるようにする

### 2.2 ユーザー価値

- 飲食店はランチの店内メニューを、配達メニューと別に出せる
- 参加者は店内イベントで、その時間帯のメニューだけを見る

### 2.3 成功指標（KPI）

- イートイン業態に配達距離帯が保存された件数: 0 件

## 3. 前提条件

### 3.1 技術的前提条件

- 業態ドキュメントの共通項目は [03](./03_複数店舗・複数メニューリスト.md) §5
- 現行の `min_orders_on_spot` はイートイン最低保証としては使わない

### 3.2 ビジネス的前提条件

- Phase 2 のイートインは「イベントの提供方法が店内」であり、空席予約ではない
- 最低保証を請求する相手（参加者、主催者、店舗）は未決。決まるまで金額フィールドを持たない

### 3.3 依存関係

- [03](./03_複数店舗・複数メニューリスト.md) Phase 2
- オプション表示は [02_オプションメニュー.md](./02_オプションメニュー.md)

## 4. 画面仕様

### 4.1 画面遷移

店舗編集の業態一覧から、種別イートインで業態を追加する。流れは 03 §4。

### 4.2 UI要素

- 03 §4.2.2 の共通項目
- 注文期限は分前のみ。日前の時刻指定は出さない
- 距離帯、配達主体は出さない
- 部屋リストは出さない

保存時、`service_format == eatin` なら `order_deadline.kind` は `minutes_before`。`range_bands` と `delivery_provider` は書けない。

## 5. 技術仕様・データ構造設計

### 5.1 スキーマ

共通スキーマは 03。イートインで必須になる差分は次のみ。

| フィールド | 内容 |
| :-- | :-- |
| `service_format` | `eatin` |
| `order_deadline` | `{ kind: 'minutes_before', minutes_before: 1〜10080 }` |

`upsertServiceFormat` が上記以外を拒否する。

### 5.2 将来（部屋を入れる条件）

次が仕様で決まってから `shops/{shopId}/rooms/{roomId}` を追加する。

- 予約の単位（イベントが部屋を占有するのか、席数だけ消費するのか）
- 最低保証料金の請求先と、既存の請求書・Stripe のどちらに載せるか
- 同じ時間帯に複数イベントが同じ部屋を取れないことの保存方法

そのときのフィールド案は、部屋名、画像、`seats_min`、`seats_max`（`seats_max >= seats_min`）、最低保証額。業態からは `room_ids` で参照する。本書の Phase 2 には含めない。

### 5.3 Functions

03 の `upsertServiceFormat` に含まれる。イートイン専用の Function は作らない。

## 6. 実装優先度

- **Phase 2**: 業態 `eatin`（部屋なし）
- **それ以降**: 部屋と最低保証。条件は §5.2

## 7. 注意事項

- 検討資料の `room_count_min` を最大席数にも使う定義は採用しない
- 店舗主催（店が自分でイベントを作る）は、業態フラグでは表現しない。イベント作成権限の別仕様にする
