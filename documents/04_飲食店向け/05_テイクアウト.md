# テイクアウト

- **ステータス**: 仕様（未実装）。業態 `takeout` は [03_複数店舗・複数メニューリスト.md](./03_複数店舗・複数メニューリスト.md) Phase 2
- **関連仕様書**: [03_複数店舗・複数メニューリスト.md](./03_複数店舗・複数メニューリスト.md) / [04_イートイン.md](./04_イートイン.md)

## 1. 概要

### 1.1 機能の目的

店舗のテイクアウトを、デリバリー・イートインとは別の業態として、時間帯とメニューリストと注文期限で設定する。

### 1.2 主要な機能

- 業態種別 `takeout`
- 注文期限は提供開始の何分前
- 最小注文金額と 1 注文あたり最大個数は任意
- 配達距離、配達主体、部屋は持たない

### 1.3 対象ユーザー

- **飲食店**: テイクアウトの時間帯とメニューを設定する
- **主催者・参加者**: その時間帯のメニューをイベントで注文する

### 1.4 スコープ外

- 受け取り時間の枠予約（来店時刻のスロット）
- 個数での最低注文。最低は金額のみ
- 配達料

## 2. ねらい

### 2.1 ビジネス目標

- 短時間の持ち帰りと、前日締切の配達を同じ店舗で併存させる

### 2.2 ユーザー価値

- 飲食店は「開始 60 分前まで、ランチメニュー」を配達設定と別にできる

### 2.3 成功指標（KPI）

- テイクアウト業態に配達距離帯または部屋 ID が保存された件数: 0 件

## 3. 前提条件

### 3.1 技術的前提条件

- 業態の共通項目は [03](./03_複数店舗・複数メニューリスト.md) §5
- 現行店舗の注文期限は日前＋時刻（デリバリー向け）。テイクアウトは分前だけを使う

### 3.2 ビジネス的前提条件

- 受け取り場所は店舗住所（現行 `PartnerShop` の住所）。別の受け取り窓口は持たない

### 3.3 依存関係

- [03](./03_複数店舗・複数メニューリスト.md) Phase 2
- [02_オプションメニュー.md](./02_オプションメニュー.md)

## 4. 画面仕様

### 4.1 画面遷移

店舗編集の業態一覧から、種別テイクアウトで業態を追加する。流れは 03 §4。

### 4.2 UI要素

- 03 §4.2.2 の共通項目
- 注文期限は分前のみ
- 距離帯、配達主体、部屋は出さない

保存時、`service_format == takeout` なら `order_deadline.kind` は `minutes_before`。`range_bands`、`delivery_provider`、部屋参照は書けない。

同一店舗でテイクアウト同士の曜日と時間帯が重なる場合は保存しない（03 の重複規則。種別が違えば重なってよい。例: 同じ昼にデリバリーとテイクアウト）。

## 5. 技術仕様・データ構造設計

### 5.1 スキーマ

| フィールド | 内容 |
| :-- | :-- |
| `service_format` | `takeout` |
| `order_deadline` | `{ kind: 'minutes_before', minutes_before: 1〜10080 }` |

例: 平日 11:00–13:00、期限 60 分前、最大 1 注文 10 個、リストはランチ。

### 5.2 Functions

03 の `upsertServiceFormat`。テイクアウト専用の Function は作らない。

## 6. 実装優先度

[03](./03_複数店舗・複数メニューリスト.md) Phase 2 で `delivery` / `eatin` と同時に入れる。単独の先行リリースはしない。

## 7. 注意事項

- 現行の `shop_deadline_datetime`（日前）をテイクアウトに流用しない
- 最大個数は 1 注文あたり。イベント全体の食数上限は `limit_per_event`（[14_限定食数機能.md](./14_限定食数機能.md)）
