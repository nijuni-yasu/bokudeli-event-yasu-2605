# メール_コミュニティメンバー_新着イベント.md

## 機能概要

- 「新着イベント」をコミュニティメンバー全員に配信する。

## 送信先

コミュニティメンバー全員（メールアドレス未設定者を除く）。配信停止した宛先は SendGrid が抑止する。

## 送信条件・送信済みフラグ

- `is_public`:`true` なオープンなイベントのみ
- エンタープライズイベントは対象外
- 誰か最初に注文したタイミングで送信する
- 送信するのは1回のみ。
- 専用の配信停止グループIDが正の安全な整数として設定されている場合のみ送信する。未設定・不正な場合は警告ログを出し、送信先の取得と送信済みフラグの更新を行わない。設定後、次に注文が確定したタイミングで再判定される（自動再送は行わない）。
- `sent_new_event_mail_at`: Firestore では `timestamp`、アプリ側では epoch millis でフラグ管理する。送信前にトランザクションでイベントを更新し、並行実行による重複送信を防ぐ。送信失敗時もフラグを維持する。
- 送信先が0件の場合もフラグを更新しない。
- logについては `updated_by`:`user_id` 最初に注文したユーザーとする

## 送信する変数

- コミュニティ名
- イベントURL
- イベントタイトル
- イベント画像
- イベント説明文
- 開催日時・終了日時
- 開催住所・開催場所
- 飲食店名
- 注文期限
- 支払方法

## 配信停止グループ（#2369）

- 新着イベント通知専用の Unsubscribe Group「shokujii コミュニティ新着イベント」（ID: `36042`）を使用する。説明は「コミュニティの新着イベントをコミュニティメンバーにお知らせします」。
- ID は `functions/default/src/utils/mail.ts` の `NEW_EVENT_NOTIFICATION_ASM_GROUP_ID` で管理する。`36042` の作成・設定は確認済み。テンプレートの配信停止リンクと実配信の抑止は別途確認する。
- `sendNewEventNotificationToMembers` の一括送信に `asm: { groupId: NEW_EVENT_NOTIFICATION_ASM_GROUP_ID }` を指定する。既存の開催案内・人気イベント・チャット未読通知のグループは流用しない。
- 配信停止はコミュニティ単位ではなく、新着イベント通知全体に適用する。同グループで配信停止した宛先への以降の通知は SendGrid の group suppression により抑止する。Firestore 側に配信停止状態を重複保存しない。
- 参加者・主催者への注文完了メールや他種別の通知には、このグループを付与しない。既存のグローバル配信停止設定はそのまま尊重する。

### SendGrid 設定・有効化の手順

1. Unsubscribe Groups の「shokujii コミュニティ新着イベント」（ID: `36042`）を使用する。
2. 上記 Dynamic Template の有効なバージョンに、グループ用の配信停止リンクを追加する。日本語文言の例:

   ```html
   <a href="<%asm_group_unsubscribe_raw_url%>">新着イベント通知の配信を停止する</a>
   ```

   `asm.groupId` の指定だけではテンプレート本文のリンク追加を代替できない。全メール停止用の `<%asm_global_unsubscribe_raw_url%>` は使わない。
3. `NEW_EVENT_NOTIFICATION_ASM_GROUP_ID = 36042` を設定した Functions を反映する。
4. 許可された検証用宛先で、配信停止リンクの表示・遷移先が専用グループであることを確認する。同グループで停止した宛先への次回新着通知が抑止され、注文完了メールには影響しないことを確認する。ローカルのモックテストだけでは SendGrid 側の設定・抑止は検証できない。

参照: [SendGrid のグループ配信停止タグ](https://www.twilio.com/docs/sendgrid/ui/sending-email/group-unsubscribes)、[Suppression Groups](https://www.twilio.com/docs/sendgrid/for-developers/sending-email/suppressions)
